# Findings for events (C:\Users\vagrant\Downloads\EnergyPod\pod-manager\tests\unit\test_event_bus.py)

## Author notes
Decisions the primary must reconcile: (1) publish shape aligned to the concurrent tests/unit/test_service_facade.py FakeEventBus (publish(body mapping) -> int) rather than publish(type=, payload=); body supplies type/payload, the bus adds sequence and occurred_at and must OVERRIDE caller-supplied sequence/occurred_at (server-assigned metadata). Pinned that event dicts contain exactly the four keys type/sequence/occurred_at/payload — no bus-added event_id/uuid; if an implementation wants extra fields, this suite must be relaxed first. (2) Constructor kwargs pinned as retention=, queue_capacity=, clock= (Clock-port object, matching kernel/actor style; AuditEventFactory uses wall_now= callable instead). The composition-root suite being written concurrently must use these same names. occurred_at must be a JSON-serializable string derived from the injected clock (exact ISO format unpinned, but two buses with identically-advanced clocks must produce identical occurred_at values). (3) Marker vocabulary left open: recognized as a dict whose type matches resync|gap|discontinuity (case-insensitive) or that carries an explicit truthy flag among discontinuity/gap/resync/resync_required; the marker may omit 'sequence' (rest._stream_events converts it to its own resync_required close). (4) Discontinuity boundary pinned exactly: marker iff after_sequence + 1 < oldest retained sequence; stale subscribers then receive only events newer than the snapshot at subscribe time (no retained-window replay) per 'starts at the next event after the window'. (5) Sequence base pinned to first event = 1 with fresh snapshot_sequence() == 0, which is required for the adapter's contiguity check (expected = snapshot + 1). (6) subscribe(after_sequence=None) semantics (cursor-less client) deliberately unpinned — protocol allows None but the adapter always passes an int; primary should decide whether None means live-only or full-window replay. (7) Bounds rejection pinned to ValueError including bool True (rest.py capacity precedent), not TypeError.

## Findings

### [1] P1 - Replay-to-live seam untested; live-event-skip mutant passes all 24 tests
Category: coverage-hole

No test subscribes with an in-window cursor and then publishes new events: every replay test (test_subscribe_yields_exactly_the_events_after_the_cursor, test_retention_window_boundary_is_exact, test_subscribers_with_different_cursors_are_isolated) drains a static window with no post-subscribe publishes. Verified empirically: a mutant whose in-window path replays the window then starts live delivery at snapshot+1 (silently skipping the first live event) passes all 24 tests. That directly violates API_CONTRACTS.md 'subscribe(after_sequence) yields events with sequence > after_sequence in order' and is precisely the failure rest.py:_stream_events (lines 604-618) kills the socket for (terminate('sequence_gap')). The fresh-bus live path is covered (test_many_publications, the gated consumer), so the uncovered seam is specifically populated-window replay transitioning into live events without a gap, duplicate boundary event, or marker.

Suggested fix: Add a test: with retention=8 publish 30 events, subscribe(after_sequence=26), then publish events 31 and 32 while draining, and assert the delivered sequences are exactly [27, 28, 29, 30, 31, 32] with no marker between the replayed tail and the live head.

### [2] P1 - Exact-key-set pin rejects a doc-compliant event envelope such as event_id
Category: contract-conflict

Line 353 asserts set(event) equals exactly the four contract keys. API_CONTRACTS.md lines 199-200 say bodies 'carry type, sequence, occurred_at, and a minimal payload' - 'carry' does not forbid additional envelope keys, and the WebSocket adapter forwards events verbatim checking only 'sequence', so an implementation adding an event_id or schema version violates no written contract. Verified empirically: a contract-faithful reference implementation that adds an event_id key fails this one assertion and nothing else. The author flagged this as a primary decision, but as written the suite blocks a doc-compliant shape. The caller-forgery test already proves sequence/occurred_at are server-overridden and payload faithfulness is pinned separately, so the exact-set equality adds only the extra-key prohibition.

Suggested fix: Either relax to asserting the four contract keys are present with correct types (subset check), or first amend API_CONTRACTS.md to state the event envelope is exactly these four keys so the pin is granted rather than invented.

### [3] P2 - occurred_at clock derivation is not enforced; counter-stamp mutant passes green
Category: vacuous-assertion

The author report claims 'occurred_at driven by the injected clock', but no assertion ties occurred_at to the clock's value. The only checks are pairwise: first != second (line 363) and left-bus == right-bus projections (line 440). Verified empirically: a mutant stamping occurred_at = 't<sequence>' (clock never read) passes all 24 tests; an ambient-clock mutant was caught only accidentally (this VM's coarse clock resolution made two consecutive datetime.now values identical), and the two-bus determinism test itself PASSED with ambient time. So clock derivation is enforced by resolution luck, not deterministically, and non-timestamp stamps are never rejected.

Suggested fix: Keep the format unpinned but pin derivation: assert datetime.fromisoformat(first['occurred_at']) equals FakeClock's base instant and second equals base + 5 seconds (the FakeClock base is fixed at 2026-08-21T00:00:00Z, so this is deterministic without pinning ISO formatting choices).

### [4] P2 - Gated-consumer bounded-delivery assertion cannot fail (harness reads at most 3 items)
Category: vacuous-assertion

In test_gated_slow_consumer_never_stalls_publishes_and_gets_a_resync_marker, line 308 asserts len(delivered) < 12 as 'the per-subscriber queue must stay bounded', but gated_reads (lines 281-287) reads at most 3 items, so delivered has length at most 3 always and the assertion cannot fail. Line 309's delivered == sorted(set(delivered)) is near-inert at three or fewer items. The claimed bounded-delivery pin proves nothing; only the marker-existence (line 304) and publish-completion/snapshot==13 (lines 292-300) assertions have teeth. A reader of the suite would believe queue boundedness is proven when it is not.

Suggested fix: After the marker is found, keep draining (e.g. 16 reads) and assert the total delivered events is bounded well below the 12 published, or delete the vacuous line and rely on the marker assertion as the boundedness proof.

### [5] P2 - Credential-free test is circular and can never fail independently
Category: vacuous-assertion

test_event_bodies_stay_credential_free publishes payloads that contain no credential-shaped keys by construction, then asserts credential_shaped_keys(event) == [] (line 406). Combined with payload faithfulness (line 409) and the exact-key-set pin elsewhere, no implementation state fails this test without already failing another: the bus cannot filter payloads (they must pass through equal), and any bus-injected credential key is already excluded by the exact-key-set test. The 'FakeClock not in encoded' check (line 408) is equally unreachable since a non-JSON-serializable clock object would make json.dumps raise first. API_CONTRACTS.md line 199 'Event bodies are ... credential-free' is thus covered in name only; the real obligation sits with publishers (facade), not the bus.

Suggested fix: Either delete the test and cover credential exclusion in the facade suite where publications originate, or convert it into a meaningful pin: publish a payload containing a credential-shaped key and assert the bus passes it through verbatim while adding no credential-shaped keys of its own (documenting that the bus is explicitly not a filter).

### [6] P2 - ValueError-including-bool constructor pins go beyond the documented contract
Category: contract-conflict

test_constructor_rejects_non_positive_bounds (lines 165-179) demands ValueError for retention/queue_capacity of 0, negatives, and bool True. Neither API_CONTRACTS.md's event-bus section nor ADR-0003 D3 says anything about constructor validation or exception types. The claimed rest.py precedent is mixed: idempotency_capacity excludes bool (rest.py line 213) but websocket_queue_capacity (lines 211-212) only checks < 1 and would accept True. A doc-compliant implementation that raises TypeError for a bool, or validates only with retention < 1 and therefore accepts True == 1, fails this suite. Also the test name says non-positive bounds while True is positive, so the name misdescribes two of the six cases.

Suggested fix: Either soften to pytest.raises((ValueError, TypeError)) and drop the bool cases, or record the ValueError-including-bool rule in API_CONTRACTS.md's event-bus section (mirroring the idempotency_capacity precedent) so the pin is granted by contract text.

### [7] P2 - subscribe(after_sequence=None), legal per the EventSource protocol, is never exercised
Category: coverage-hole

The production EventSource protocol (src/energypod/api/rest.py line 49) types subscribe(*, after_sequence: int | None), and the suite pins keyword-only calling (subscribe(0) -> TypeError, line 465), yet no test ever calls subscribe(after_sequence=None). The adapter always passes an int today, so the author deliberately left semantics unpinned - but that means an implementation that raises on None, or treats it as 0 (full replay) versus live-only, passes the suite unchanged while diverging on a value the protocol declares legal. Since EventBus is contracted as the only EventSource, protocol conformance for None is arguably in scope here even if live-only-versus-replay semantics stay unpinned.

Suggested fix: Add a minimal conformance smoke test: bus.subscribe(after_sequence=None) returns an object with __aiter__/__anext__ without raising (None semantics left for the primary to pin separately, per the author's note). If the primary decides None is out of contract for EventBus, narrow the EventSource protocol signature in rest.py instead.
