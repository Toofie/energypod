## Findings

### [1] P1 - Reconnect scenario forces fence-invalidated authorization peek that no contract grants and the accepted facade contract contradicts
Category: inventing contract

Scenario 5 asserts unit_view(refused_snapshot)["authorized_power"] is None at wall-monotonic t=1.60 for a capability that was published at t=1.20 with authorization_lifetime_s=1.2 (unexpired until 2.40) and never consumed by a heartbeat. Timeline: evidence poll t=1.20, tick publishes authorization, drop/restore link, reconnected poll advances 0.40 s to t=1.60, then refused_snapshot. The only delta between armed_snapshot (authorized 250, line 881) and refused_snapshot is the generation fence. API_CONTRACTS grants write-time fencing only ('It writes only if authorization is current, generation is not older...'); CONTINUITY says late work 'cannot regain authority', i.e. the write gate. Nothing grants that a fence evicts the capability from the repository or that peek/current validates generation, and the accepted facade contract test's FakeAuthorizationRepository.peek (tests/unit/test_service_facade.py:170-174) is a plain slot read with no generation awareness. A conformant implementation that relies solely on the contracted write-time gate (matching the facade fake's peek semantics) leaves the slot populated until 2.40 and fails this assertion.

Suggested fix: Either (a) advance the clock past authorization_lifetime_s (or consume via a refused heartbeat) before asserting authorized_power is None so the assertion rests on contracted single-use/expiry semantics, or (b) make the pin explicit and doc-granted: extend API_CONTRACTS (facade snapshot or authorization repository) to state that a fencing event invalidates the published authorization projection, and note the facade peek must consult the fence, so the composition has exactly one granted mechanism to satisfy it.

### [2] P1 - Scenario 2's clamp golden number silently pins heartbeat_interval_s <- control_period_s, an undisclosed config-to-policy mapping
Category: inventing contract

RAMP_ALLOWANCE_W = int(750 * CONTROL_PERIOD_S) = 300 W is folded into expected authorized watts (line 725-731: min(static 3000, dynamic, 300)). But the safety kernel's ramp bound is ramp_limit_w_per_s * policy.heartbeat_interval_s (src/energypod/application/safety.py:302, pinned by tests/unit/test_safety.py:705 with heartbeat 1.0), and ControllerConfig has NO heartbeat field at all (grep of src/energypod/runtime/config.py: zero hits). The composition must invent the mapping; if it maps heartbeat_interval_s to anything other than exactly control_period_s=0.40 (e.g. authorization_lifetime/2 = 0.6 -> 450 W allowance), authorized becomes min(3000, dynamic>=400, 450) != 300 and the test fails against a contract-conformant build with a misleading 'clamp' diagnosis. The author's own disclosure (note 8) lists the other unmapped policy fields (max_temperature_spread_c, apparent_power_limit_va_by_unit) but omits this one. Related: the module comment (lines 55-57) claims the 12 kW request exercises the static bound, but ramp (300) always binds first, so the static and dynamic bounds are never the binding term in any golden scenario.

Suggested fix: Derive expected watts from a ramp allowance the test itself can justify: either assert the mapping explicitly (fail with a clear message if ControlPolicy.heartbeat_interval_s != config.timing.control_period_s in the composed runtime), or raise ramp_limit_w_per_s so the static limit binds instead (e.g. ramp 7500 W/s -> allowance 3000 == static, making STATIC_UNIT_LIMIT_W the binding bound and the docstring true), or document the heartbeat mapping in API_CONTRACTS before pinning the number.

### [3] P1 - No composed fail-closed kernel path: every scripted control step ends in authority; stale-telemetry rejection, not-armed rejection, capability replay, and renewal are never exercised
Category: coverage hole

For a suite whose stated role is the integration keystone of the safety authority, every kernel tick in all six scenarios produces nonzero authority (or the emergency-stop zero). Missing: (1) the CONTINUITY non-negotiable 'missing, stale... safety inputs fail closed to zero' is never driven end-to-end -- with maximum_telemetry_age_s=2.0 the harness could clock.advance(2.5) with no poll, then control_tick, and assert a zero-authorized decision with a rejection reason and no bus authorization, proving the composed kernel/observation wiring fails closed (currently only unit-proven against hand-built observations); (2) the lifecycle_not_controllable rejection (safety.py:167) is never hit -- a dispatch+tick while the unit is qualified but not armed; (3) single-use capability replay -- a second device_heartbeat without a fresh tick must not write (CONTINUITY: 'consumed capability can never be replayed'), only implied via snapshot None; (4) the steady-state loop -- 'Repeated cycles in one healthy generation' with a second tick while ACTIVE (ramp continuing from measured 250 W, fresh cycle_id, re-authorization after the 1.2 s lifetime lapses) is never run, though it is the loop's normal operating mode and the reason the renewal machinery exists.

Suggested fix: Add at least a stale-telemetry fail-closed scenario (advance past maximum_telemetry_age_s with an active intent, tick, assert zero authorized + rejection reason + no write reaching the pod) and a replay negative (second heartbeat after the first consumed the capability, assert no second write); ideally one renewal scenario with two ticks in one generation while ACTIVE.

### [4] P2 - operator_dispatch invents an 'intent*' bus event type absent from the documented and pinned vocabulary
Category: inventing contract

assert any("intent" in event["type"] for event in fresh) after submit_intent. API_CONTRACTS' initial event-bus vocabulary is 'Observation, decision/audit, lifecycle, arming, and stop events'; test_event_bus.py's VOCABULARY (lines 25-31) contains no intent type, and tests/api/test_event_contract.py pins none either. Publication of the facade mutation is contracted, but the type name is not; a conformant facade publishing the acceptance as e.g. 'dispatch.accepted' or under the audit-append vocabulary fails this assertion. (The author's note 6 correctly grounds 'observation*', 'unit.armed', 'emergency_stop*' but does not ground 'intent*'.)

Suggested fix: Weaken to the contracted fact -- that submit_intent publishes something and appends audit (mirror assert_audited_and_published: non-empty fresh events after the mutation) -- or first pin an 'intent.accepted' type in the event-bus vocabulary (test_event_bus.py VOCABULARY / API_CONTRACTS) so the substring has a grounded source.

### [5] P2 - Reconnect pins an undocumented actor state machine: immediate OBSERVE_ONLY (never DISCONNECTED) and re-qualification to DISARMED via stable samples
Category: brittle coupling

After drop_link()/restore_link() and exactly one successful poll, the actor must be UnitLifecycle.OBSERVE_ONLY, and after further polls it must reach DISARMED on the same stable-sample path as inhibit recovery. UnitLifecycle has a DISCONNECTED state and the docs never specify the reconnect transition: a conformant implementation that enters DISCONNECTED on detecting the epoch change and returns to OBSERVE_ONLY only after re-verifying profile/identity (one extra exchange) fails line 856 despite nothing in API_CONTRACTS, ADR-0003, or CONTINUITY forbidding it. The fencing and re-arm requirements themselves are grounded; the exact intermediate states are not.

Suggested fix: Assert the granted invariants instead of exact states: lifecycle not in {ARMED_IDLE, ACTIVE} (no control authority) immediately after the epoch change, and DISARMED only after the configured stable_samples_to_rearm new-epoch polls (an assertion the current 'after three polls' placement only weakly implies).

### [6] P2 - Determinism scenario is vacuously equal for absent audit fields and blind to cross-process nondeterminism
Category: vacuous assertion

audit_projection builds records via getattr(event, field, None): if the implementation simply lacks a field (e.g. policy_version or observation_sequences never populated on facade audit events), both runs project None and the equality passes -- the determinism test cannot fail on missing attributes, and no other golden assertion pins those fields for non-decision events. Additionally both builds run in one process, so per-process sources of divergence (hash-seed-dependent set iteration order, per-process random seeds) cannot be caught even though ADR-0003 D4's determinism claim is about identical scripts producing identical audit/bus streams across deployments.

Suggested fix: Assert presence and canonical types of the projected fields for at least the control_decision and one facade mutation event (reason_codes tuple, non-None cycle_id/generation/policy_version), before comparing runs; optionally run one build in a subprocess if cross-process determinism is in scope.

### [7] P2 - compose_runtime/simulator_handle misreport internal implementation bugs as missing-contract failures
Category: red-phase hygiene

compose_runtime wraps the build_runtime call in 'except TypeError' and pytest.fails with 'build_runtime must accept simulate= plus an injected deterministic clock='; simulator_handle likewise converts AttributeError/KeyError/TypeError from runtime.simulators into 'must expose per-unit scenario handles'. Once the signature/hooks exist, any TypeError/AttributeError raised inside a correctly-shaped implementation (e.g. a None arithmetic bug, or a connection_epoch property whose getter raises AttributeError) is reported as a contract-is-not-implemented failure, sending the implementer to change a signature that is already correct. The original error text is appended, which mitigates but does not fix the misclassification.

Suggested fix: Probe the signature without executing it (inspect.signature checks for 'simulate'/'clock' parameters) and let runtime TypeErrors propagate as ordinary failures; in simulator_handle, catch only the lookup (runtime.simulators access) and attribute absence (inspect.getattr_static or hasattr) rather than blanket exception types.
