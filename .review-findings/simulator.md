## Author notes
Contract surface I had to invent (docs specify behavior, not signatures); primary must reconcile with the implementer and any golden-scenario agent: (1) Constructors pinned as SimulatedEnergyPod(clock=, identity=, bic_count=, seed=, watchdog_timeout_s=, cell_poll_interval_s=) with clock needing only monotonic(), and SimulatorTransport(pod=). (2) "Poll" semantics pinned: one FC03 read whose window includes telemetry anchor register 0x5000 advances the device model (telemetry_sequence +1, telemetry_captured_at_mono = injected now); other block reads and writes do not. Whether the 7-register probe itself counts as a poll is deliberately unpinned (only relative increments asserted). (3) Device-model attribute names pinned: telemetry_sequence, telemetry_captured_at_mono, cell_sequence, cell_captured_at_mono; scenario hooks pinned as inject_fault(prefix, bit)/clear_fault(prefix, bit) keyed on faults.FAULT_CATALOG prefixes (e.g. "Stack_Fault0", "PCS_Warning0"); pod.identity mirrors the constructor value. (4) Sign convention decision: measured battery watts must equal applied P bit-exactly (corroborated negative-P-charges convention made literal); objective readback is (P,Q) while latched and (0,0) after expiry/stop. Watchdog tested strictly inside (timeout-1ms) and strictly past (timeout+1ms) the boundary; the == boundary and whether expiry zeroes the objective readback (pinned: it does) are decisions to confirm. Each accepted write renews the lease. (5) Error taxonomy: ValueError for protocol violations (write gate, malformed frames, illegal address/count, unmapped/gap reads, count>125); builtin ConnectionError for pre-connect/post-close/connect-after-close (chosen so TransportConnectionError subclasses satisfy it). (6) Extra coherence pins beyond the minimum: DCDC battery voltage 0x2000+3 == BMS pack voltage 0x5000+6, DCDC battery power 0x2000+9 == BMS battery power 0x5000+8, exact extrema coherence, and 0x8106 RTU-ID readability/stability. (7) Deliberately not pinned: disconnect/malformed-register hooks (other scopes), different-seed divergence (would forbid a fully deterministic non-random model), wall-clock absence beyond what same-seed determinism implies, pod-level write API (write gate pinned at the transport per ADR D4). Cell refresh boundary pinned at >= cell_poll_interval_s since last capture, evaluated at anchor-poll time (tested at 4.9s unchanged / 5.1s refreshed).

## Findings

### [1] P1 - Endianness/word-order pins are vacuous: every energy and RTU-ID assertion is unfalsifiable
Category: vacuous-assertion

decode_uint32 returns (high<<16)|low * 0.1 for words already validated as 0..0xFFFF (read_iot_plan asserts range/type before every decode), so `assert charge_energy >= 0 and discharge_energy >= 0` (line 183), all six `assert protocol_codec.decode_uint32(field, pair) >= 0` totals (line 188), and `assert rtu_id >= 0` (line 504) can never fail for any register content (verified empirically: minimum possible decode is 0.0). The word order is baked into the production codec itself, so a simulator serving IoT BMS/total energies HIGH-word-first -- directly contradicting PROTOCOL_EVIDENCE.md section 6 ('IoT BMS charge/discharge energy ... Low word', 'no global endian rule' is a CONTINUITY protocol fact) -- passes the suite unchanged. The docstring and author report claim these tests lock 'low-word-first IoT energies'; they lock nothing.

Suggested fix: Replace with an independent expectation: drive the model to a state where the accumulated energy is computable (e.g., hold a known P for an injected duration and assert the decoded energy equals P*t/3600*10 counts within the seeded schedule's contract), or at minimum pin a seed-derived golden value, or assert the decoded value is plausible (< 1e7) so a word swap producing 4.29e9-scale values fails. For RTU ID, assert the two words decode to a specific value tied to the `identity` argument.

### [2] P1 - Invented precision: measured battery watts must equal P bit-exactly and objective readback must zero on expiry
Category: contract-conflict

API_CONTRACTS grants only 'latches applied 0x0200 PQ writes, expires to idle under watchdog timeout, derives deterministic telemetry from the applied setpoint'; ADR-0003 D4 says the same. PROTOCOL_EVIDENCE marks the sign convention only 'Corroborated operationally' and 'Firmware fallback when renewals stop | Unknown'. The suite pins (a) measured battery watts == active_w exactly within one poll (line 213, 219, 228, 243, 261) -- a contract-plausible model with a first-order ramp, efficiency factor, or per-poll settling fails; (b) 0x1060+17/+18 readback == (0,0) after watchdog expiry (line 248, 241 in scenario) -- a model whose objective registers hold the last commanded frame while going idle is evidence-consistent and fails. Stop-frame readback (0,0) is fine (it follows from latching [1,0,0]). These unratified decisions will be frozen into golden-scenario bytes.

Suggested fix: Ratify explicitly with the primary and golden-scenario agent, or weaken to the contract-granted core: measured watts must be 0 when idle/expired and must take the sign of P with bounded magnitude (e.g., abs(measured) <= abs(P) or == P within a stated tolerance) while latched; leave post-expiry readback content unpinned (assert only measured power is 0).

### [3] P1 - Disconnect and malformed-register scenario hooks: contract-named behavior with zero tests in this suite
Category: missing-coverage

API_CONTRACTS 'Deterministic simulator' and ADR-0003 D4 context name four injectable scenario families: 'faults, warnings, disconnects, and malformed registers'. This suite pins only inject_fault/clear_fault (faults/warnings). The author declares disconnect/malformed hooks 'other scopes', but the orchestrator's expected production API names only energypod.simulator.pod and energypod.simulator.transport -- the modules this file contracts. If the golden-scenario agent does not independently pin hook names and semantics (e.g., inject_disconnect()/inject_malformed_register(address, ...)), an implementation may omit them entirely and stay green, leaving the actor's reconnect/inhibit/write-failure-revocation paths untestable in the `simulate` deployment target.

Suggested fix: Either add minimal hook-shape tests here (inject a disconnect, assert read/write raise the transport connection error and that recovery/reconnect semantics or a fresh pod are deterministic; inject a malformed register word, assert the production decoder's validation raises), or obtain written confirmation from the primary that the golden-scenario suite covers both hook families with named expectations.

### [4] P2 - Layout-probe test restates the production decoder's own arithmetic in four unfalsifiable assertions
Category: vacuous-assertion

`assert probe.enable_mask == probe_registers[4] & 0xFF` is an identity: detect_layout computes enable_mask as exactly that mask for IOT (verified). `assert probe.becu_count >= 1` is forced by the decoder (max(1, popcount)). `assert probe_registers[0] > 10` is implied by `probe.layout is ProtocolLayout.IOT` on the next line. `assert cell_map.map_non_overlapping is True` is pure arithmetic on the constructor's bic_count in {1,3,6} and cannot see the simulator. These pad the suite as if they constrained the device while a simulator serving 0x1F00 in the enable word (high garbage bits, masked away by the decoder) or any degenerate BECU encoding passes.

Suggested fix: Delete the four restatements or replace with device-constraining pins: assert the raw enable-mask word has no bits above bit 7 set and popcount matches the served topology's BECU count, and assert the raw probe word 0 is a specific stable value (e.g., equals the version/identity register the model serves).

### [5] P2 - Write-gate rejection is only ever proven from an idle unit, never against a latched objective
Category: missing-coverage

Every write-gate parameter starts from a fresh idle unit, so the post-rejection checks `applied_objectives == (0,0)` and `measured_battery_watts == 0` cannot distinguish 'rejection left state untouched' from 'rejection reset an active objective'. An implementation whose gate-validation path clears the latched setpoint (or half-latches a header-only frame) before raising would pass all 18 cases. The docstring claim 'neither latches an objective nor disturbs idle telemetry' is therefore weaker than the safety-relevant property: a garbage write during an active 2200 W dispatch must not alter it.

Suggested fix: Latch a valid frame first, then attempt each refused write, then assert measured watts and objective readback still equal the latched values (or at minimum add one such case per error family -- wrong address, bad header, bad length, non-integer value).

### [6] P2 - Identity is never tied to the wire: pod.identity mirror plus unconstrained 0x8106 content
Category: vacuous-assertion

`assert pod.identity == 'SIM-BEP-0042'` only checks the object stores its constructor argument (a mirror tautology). The 0x8106 test asserts only that two reads return the same words and that a uint32 decode of them is >= 0 (always true). An implementation that ignores `identity=` entirely and serves constant 0x0000,0x0000 passes. API_CONTRACTS says the model exposes 'identity/profile registers'; nothing in the suite makes the identity parameter observable, so the constructor argument is dead weight the suite cannot detect.

Suggested fix: Pin a decodable relationship, e.g., assert the RTU-ID words decode through UInt32Field.RTU_ID to a value derived from the identity string (hash/stable mapping pinned once), or at least assert the words are non-zero and differ between two pods built with different identity arguments.

### [7] P2 - Anchor-window poll semantics are an invented mechanism that also couples to the golden-scenario agent
Category: contract-conflict

The contract says only 'advances monotonic telemetry/cell sequences per poll' without defining a poll. The test pins that reads of 0x1000 and 0x4101 do NOT advance telemetry_sequence while any read covering 0x5000 does, each by exactly 1. An implementation that treats every FC03 transaction (or every full iot_reads plan) as one poll -- a defensible reading -- fails line 364 despite conforming. Separately, the production actor polls all 12 IoT blocks per cycle, only one of which contains 0x5000, so the sequence-per-cycle rate the kernel/audit path observes depends entirely on this unpinned definition; if the golden-scenario agent assumes per-cycle, its expected audit sequences will diverge from any implementation built to pass this file.

Suggested fix: Keep the pin but have the primary record it in API_CONTRACTS/A DR as the normative poll definition ('one device poll = one FC03 read whose window includes 0x5000') before implementation, and confirm the golden-scenario and composition tests derive their expected sequence counts from the same rule.

### [8] P2 - 'Seeded schedule' telemetry dynamics are unenforced: a static register bank passes everything
Category: missing-coverage

The only registers the suite ever observes changing are bms[8] (battery watts) and 0x1060+17/+18 (objectives). No test asserts SOC moves, energies accumulate under load, temperatures/cells ever change after a refresh, or that two polls with an applied setpoint differ in anything beyond the power words. Combined with the deliberate omission of different-seed divergence, `seed=` is a dead parameter as far as this suite can tell: an implementation with no seeded schedule at all (constant bank + power passthrough) passes, including the byte-identical determinism test, whose three decode assertions only re-check values other tests already pin.

Suggested fix: Add one dynamics pin: hold a known setpoint across injected time and assert at least one derived quantity changes in a deterministic, seed-sensitive direction (e.g., energy delta is non-zero and identical across two same-seed runs while the value itself is pinned), so a static bank fails and the seed parameter has observable meaning.
